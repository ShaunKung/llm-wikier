## 功能说明

`wiki-capture` 不通过用户手动调用。Agent 在对话中自动感知新信息后加载本 skill，按照标准化流程将对话中的知识沉淀到 wiki。

## 触发条件

Agent 应在对话中出现以下信号时自动触发本流程（宽松捕获）：

**应触发**：
- 用户陈述了一个明确的事实/数据（"X 成立于 2018 年"）
- 用户纠正了此前的说法（"不对，之前说的那个数字是错的"）
- 用户表达了决定或偏好（"我决定用方案 B"）
- 用户分享了新的洞察或发现（"刚意识到 A 和 B 之间可能有这样的关系"）
- 用户对已有实体/概念提供了补充信息

**不应触发**：
- 日常闲聊、寒暄
- 纯粹基于 wiki 内容的查询和回答
- 用户要求汇总已有信息
- 用户要求删除或清理内容（使用 `/wiki-prune`）
- 用户已主动调用了 `/wiki-ingest` 或 `/wiki-update` 处理文件

## 执行流程

### Phase 1: 识别

1. 从对话中提取一句话概括新知识的内容
2. 判断知识类型：**事实** / **纠正** / **决定** / **观点** / **补充**

### Phase 2: 比对

1. 搜索 `.wiki/entities/`、`.wiki/concepts/`、`.wiki/analysis/` 中可能相关的页面
2. 阅读匹配度最高的页面内容
3. 判断新知识与已有内容的关系：
   - **全新知识**：wiki 中不存在的实体/概念/事实
   - **补充知识**：wiki 中已有相关页面，新信息可追加
   - **冲突知识**：新信息与 wiki 中某页面内容不一致

### Phase 3: 处理

#### 全新知识

```
根据我们的对话，我注意到以下新信息：

  "实体 X 的成立时间在 2019 年"

这尚未记录在 wiki 中。建议：
  - 创建页面: entities/X.md
  - 在其中记录成立时间及其他相关信息

是否将其沉淀到 wiki？
```

用户确认后，创建/更新相应 wiki 页面，记录到 `.wiki/log.md`。

#### 补充知识

```
根据对话，以下信息可追加到已有页面：

  "实体 X 的总部也设在东京"
  
  目标页面: entities/X.md（已有"成立时间"和"主要业务"）

是否追加到 wiki？
```

用户确认后，追加到已有页面。

#### 冲突知识

```
⚠ 发现信息冲突：

  "实体 X 的成立时间是 2019 年"（本次对话）
  "实体 X 的成立时间是 2018 年"（wiki 记录: entities/X.md）
  现有来源: articles/interview.md

请裁决：
  A. 接受新信息，更正 wiki（旧记录有误）
  B. 维持 wiki 记录，不修改（新信息有误）
  C. 两者共存，添加争议说明
```

**用户选 A**：
1. 更新 entities/X.md 中的相应内容
2. 在页面底部添加 `## 争议历史` 章节，记录本次变更：
   ```markdown
   ## 争议历史
   
   ### 成立时间
   - 原始记录: 2018 年（来源: [[articles/interview-summary|interview]]，录入于 2026-04-01）
   - 2026-05-10 用户纠正为: 2019 年
   - 处理: 更正 wiki，旧来源信息已过时
   ```

**用户选 B**：
- 不修改 wiki
- 在 `.wiki/log.md` 记录此次冲突及处理结果

**用户选 C**：
- 在相关页面添加 `## 不同来源记载` 章节：
   ```markdown
   ## 不同来源记载
   
   ### 成立时间
   - 2018 年: 来源于 [[articles/interview-summary|interview]]
   - 2019 年: 来源于用户对话记录（2026-05-10）
   - 待进一步核实
   ```

## 写入目标对照表

| 知识类型 | 目标位置 | 示例 |
|---------|---------|------|
| 新实体的事实 | `.wiki/entities/实体名.md`（新建） | 新建 entities/新公司.md |
| 已有实体的补充 | `.wiki/entities/实体名.md`（追加） | 向 entities/X.md 追加信息 |
| 新概念 | `.wiki/concepts/概念名.md`（新建） | 新建 concepts/新理论.md |
| 已有概念的补充 | `.wiki/concepts/概念名.md`（追加） | 向 concepts/Y.md 追加信息 |
| 分析/洞察 | `.wiki/analysis/主题.md`（新建） | 新建 analysis/A与B的关联.md |
| 用户决定/偏好 | `.wiki/analysis/决策记录.md`（新建或追加） | 新建 analysis/技术选型决策.md |
| 纠正（替换旧值） | 原页面（修改） + 争议历史 | 修改 entities/X.md |

## 写入规范

### 新建实体页面

```markdown
# 实体名称

## 概述
[一句话描述]

## 基本信息
[从对话提取的关键信息]

## 来源
- 用户对话记录（YYYY-MM-DD）

---
*创建时间: YYYY-MM-DD*
```

### 追加到已有页面

在原页面末尾追加新章节：

```markdown
## 补充信息（YYYY-MM-DD）

[从对话提取的补充内容]
```

同时更新页面底部的 `*最后更新: YYYY-MM-DD*`。

### 日志记录

在 `.wiki/log.md` 中追加：

```markdown
## [YYYY-MM-DD HH:MM] capture | 主题

### 来源
- 对话捕捉

### 知识类型
[事实 / 纠正 / 决定 / 观点 / 补充]

### 处理结果
- [创建/更新了哪些页面]

### 冲突处理
[如有冲突，记录裁决结果]

---
```

## 索引更新

1. 如果是全新页面，更新 `.wiki/index.md` 添加条目
2. 如果是已有页面的补充，无需更新索引

## 行为准则

- **默认提议，不自动写入**：每次捕获到新知识时先向用户提议，获得确认后再写入
- **冲突必问**：只要发现冲突，必须暂停并请用户裁决，不可自行选择
- **及时写入**：用户确认后立即写入，不推迟到会话结束
- **不重复捕获**：同一会话中已提议过的内容不再重复提议
- **安静失败**：如果用户忽略或拒绝，不反复追问

## 示例对话

```
用户: 对了，我上周了解到那个项目其实是 2020 年启动的，不是 2019 年。

Agent: [自动检测到纠正，加载 wiki-capture 流程]

⚠ 发现信息冲突：

  "X 项目启动于 2020 年"（本次对话）
  "X 项目启动于 2019 年"（wiki 记录: entities/X项目.md）
  现有来源: notes/meeting-2024-03.md

请裁决:
  A. 接受新信息，更正 wiki
  B. 维持 wiki 记录，不修改
  C. 两者共存，添加争议说明

用户: A

Agent: 已更新 entities/X项目.md：
  - 启动时间: 2019 年 → 2020 年
  - 争议历史已记录
  - 日志已更新

用户: 谢谢。

Agent: [继续正常对话]
```

## 与其他 skills 的关系

| Skill | 关系 |
|-------|------|
| `wiki-ingest` | ingest 处理文件来源，capture 处理对话来源 |
| `wiki-update` | update 针对文件变更，capture 的纠正可能与 update 的源文件产生关联 |
| `wiki-query` | 查询结果如发现新的空白领域，可触发 capture 记录 |
| `wiki-lint` | lint 发现的矛盾可能与 capture 的冲突记录有关 |
