## 功能说明

`wiki-lint` 用于定期检查 wiki 的健康状态，发现并报告问题，包括：

- 信息矛盾
- 孤立页面（没有入链）
- 缺失页面（被引用但不存在）
- 过时信息
- 断裂链接
- 数据不一致
- 幽灵条目（`.wiki-processed` 中 path 指向不存在的文件）

## 执行流程

1. **扫描所有 wiki 页面**
2. **构建链接图谱**
3. **逐一检查各类问题**
4. **生成健康报告**
5. **提供修复建议**

## 使用方法

```
/wiki-lint
```

可选参数：

```
/wiki-lint --fix        自动修复可修复的问题
/wiki-lint --deep       深度检查（包括内容一致性）
```

## 检查项目

### 1. 孤立页面检查

**问题**：页面存在但没有其他页面链接到它

**检查方法**：
- 遍历所有页面，检查 `[[]]` 和 `[]()` 链接
- 构建入链计数
- 报告入链为 0 的页面

**示例报告**：

```
### 孤立页面 (3 个)

- [[entities/孤立的实体.md]] - 无入链
- [[concepts/未引用的概念.md]] - 无入链
- [[analysis/某分析.md]] - 无入链

建议：从相关页面添加链接，或考虑删除无关页面
```

### 2. 缺失页面检查

**问题**：页面被引用但实际不存在

**检查方法**：
- 提取所有 `[[]]` 链接
- 检查对应文件是否存在
- 报告不存在的引用

**示例报告**：

```
### 缺失页面 (2 个)

- [[entities/被引用但不存在的实体]] 被引用于:
  - [[sources/source-a-summary.md]]
  - [[concepts/某概念.md]]
  
- [[concepts/待创建概念]] 被引用于:
  - [[entities/某实体.md]]

建议：创建缺失的页面，或修复错误的引用
```

### 3. 信息矛盾检查

**问题**：不同页面对同一实体的描述矛盾

**检查方法**：
- 识别同一实体在多个页面的描述
- 比较关键属性是否一致
- 检查是否已有争议说明

**示例报告**：

```
### 信息矛盾 (1 处)

实体 "某人物" 存在矛盾信息：
- [[entities/某人物.md]]: 年龄 30 岁
- [[sources/article-2024-summary.md]]: 年龄 35 岁

状态：已在 [[entities/某人物.md]] 标注争议 ✓

建议：核实正确信息，更新相关页面
```

### 4. 过时信息检查

**问题**：信息可能已过时需要更新

**检查方法**：
- 检查源文件是否有更新
- 识别长时间未更新的页面
- 对比 `.wiki/.wiki-processed` 哈希值

**示例报告**：

```
### 过时信息 (2 个源文件更新)

以下源文件已更新，wiki 页面需要同步：
- `articles/article.md` (哈希变化)
  - 影响: [[entities/某实体.md]], [[sources/article-summary.md]]
  - 建议: 运行 /wiki-update articles/article.md

- `notes/note.txt` (哈希变化)
  - 影响: [[concepts/某概念.md]]
  - 建议: 运行 /wiki-update notes/note.txt
```

### 5. 幽灵条目检查

**问题**：`.wiki-processed` 中记录的源文件路径指向不存在的文件（文件已被删除或移动后未被检测到）

**检查方法**：
- 读取 `.wiki/.wiki-processed` 的 entries
- 对每条，检查文件是否存在记录路径
- 如不存在，计算该条目的 hash，在全 KB 源文件中搜索匹配
  - 找到 → 文件被移动了，建议运行 wiki-update 自愈
  - 未找到 → 文件已删除，建议运行 wiki-prune 清理

**示例报告**：
```
### 幽灵条目 (2 个)

可恢复（文件已移动）：
- `articles/old-path.md` → 匹配到新路径 `archive/new-path.md`
  建议: 运行 /wiki-update --all-changed 自动修复

已删除（无匹配文件）：
- `notes/deleted-note.md`
  建议: 运行 /wiki-prune 清理记录
```

### 6. 索引完整性检查

**问题**：页面存在但未在索引中列出

**检查方法**：
- 扫描 `.wiki/` 目录下所有 .md 文件
- 对比 `.wiki/index.md` 的内容
- 报告差异

**示例报告**：

```
### 索引不完整 (3 个页面未索引)

未在 index.md 中列出的页面：
- [[entities/新实体.md]]
- [[concepts/新概念.md]]
- [[analysis/某分析.md]]

建议：运行索引更新或手动添加
```

### 7. 链接格式检查

**问题**：链接格式不正确

**检查方法**：
- 验证 `[[]]` 语法
- 检查相对路径是否正确
- 报告格式问题

**示例报告**：

```
### 链接格式问题 (1 处)

- [[entities/某实体.md]] (文件: concepts/某概念.md)
  问题: 链接应使用相对路径或不带 .md 后缀
  建议: [[entities/某实体]]
```

```markdown
| 总页面数 | 45 |
| 实体页面 | 20 |
| 概念页面 | 10 |
| 源文件摘要 | 12 |
| 分析页面 | 3 |
| 孤立页面 | 3 |
| 缺失页面 | 2 |
| 矛盾信息 | 1 |
| 过时信息 | 2 |
| 幽灵条目 | 2 |

## 健康评分: 85/100

## 问题详情

[上述各类问题的详细报告]

## 修复建议

[按优先级排序的修复建议]

1. 运行 `/wiki-update` 更新过时的源文件
2. 创建缺失的实体页面
3. 从相关页面添加孤立页面的链接
```

## 自动修复

使用 `--fix` 参数可自动修复部分问题：

| 问题类型 | 可自动修复 |
|---------|-----------|
| 索引不完整 | ✓ 自动添加缺失条目 |
| 链接格式 | ✓ 自动修正格式 |
| 幽灵条目 | ✓ 可自动移除（文件已删除）或更新 path（文件已移动） |
| 孤立页面 | ✗ 需人工判断 |
| 缺失页面 | ✗ 需创建内容 |
| 信息矛盾 | ✗ 需人工核实 |
| 过时信息 | ✓ 触发 update |

## 与其他命令的关系

- 发现过时信息 → 运行 `/wiki-update`
- 发现无效内容 → 运行 `/wiki-prune`
- 发现缺失实体 → 新源入库后运行 `/wiki-ingest`

## 定期维护建议

- **每周一次**：运行 `/wiki-lint` 快速检查
- **每月一次**：运行 `/wiki-lint --deep` 深度检查
- **重要更新后**：立即运行检查

## 与 wiki-capture 的协作

本 skill 执行期间，对话中可能出现对 skill 功能的说明性内容。这些内容属于基础设施域（Layer 0/Layer 1），不应被 wiki-capture 捕获。Agent 在执行本 skill 时应注意：
- 当本 skill 正在处理任务时，抑制 wiki-capture 的自动感知
- 本 skill 完成后，恢复 wiki-capture 的正常监听
